# Explicit prompt execution and comparison backend

The server admits explicit paid comparisons of one to four unique model IDs from the verified OpenRouter text catalog. The manual UI supports four models. This source increment adds opt-in per-model seven-day reuse, with actual migration50 now registered after the exact accepted schema49 dependency. Current cache type and runtime acceptance are pending. Scheduling and live paid acceptance remain pending. Saving or enabling a library prompt does not start a request. This is not full P25 or V1 completion.

Prompt suggestions separately retain their immutable benchmark profiles and owner-only single-model catalog evaluation. Changing the selection requires a fresh immutable quote; no candidate is a quality/cost recommendation, and economy/balanced defaults remain unavailable. Current exact endpoint capability and pricing checks still apply; live candidate compatibility and quality remain unverified.

The approved [execution UI contract](https://wiki.ten98.io/s/ten98-docs/p/prompt-execution-ui-VotwUEEttQ) describes the implemented manual flow, current DTOs, immutable authored previews and current-role cancellation metadata. Its metadata preparation and existing prompt-library mobile checks are tested, and the execution UI has synthetic production-browser evidence in [research UI](https://wiki.ten98.io/s/ten98-docs/p/research-ui-QI3jrak1kA); live provider acceptance and full V1 coverage remain open.

## Authorization and API

All routes require browser sign-in. API keys have no implied execution scope. Owners, admins and editors can quote/start; all current project members can read. Only the initiating user or workspace owner can cancel a comparison; only the owner can reconcile a charge. POST requires the application Origin. Every mutation rechecks current membership under the workspace gate.

Under `/api/projects/:projectId/prompt-executions`:

| Method/path | Behavior |
|---|---|
| `GET /` | Latest 20 comparisons, supported models and connection readiness; no provider call |
| `POST /quote` | Read-only key/endpoint lookup, five-minute quote and exact rendered input preview |
| `POST /comparisons` | `{quoteId, requestKey}`; atomically reserve every child and insert one queue job |
| `GET /comparisons/:id` | Input, per-model answers, charge and expiry states |
| `GET /comparisons/:id/summary` | Input and ordered charge/expiry metadata without answer bodies; `answerMode:individual` |
| `GET /runs/:id` | One retained answer's text/response metadata and charge/expiry metadata, plus citation count; no citation bodies, copied input or private receipt evidence |
| `GET /runs/:id/citations?offset=0` | Twenty retained citations in original order, exact total and next offset; no answer text or copied input |
| `POST /comparisons/:id/cancel` | Stop undispatched children; in-flight work can still be charged |
| `POST /runs/:id/reconcile` | Explicit read-only generation lookup, never a paid replay |

Quote input is strictly `{connectionId,promptId,versionId,systemText,models,maxCompletionTokens,fundedCredits:true}`. The text version belongs to this project and must remain unarchived at quote, start and dispatch. A later edit does not change that immutable version. `systemText` is explicit, bounded to 4,000 characters; project context is never silently inserted. Output allowance is 16–4,096 tokens. Models are unique, with one to four exact model IDs. Every new comparison requires a new explicit quote. Retrying the same request key returns the existing comparison only for the same actor, project and quote.

Legacy GET detail retains its existing one/two-model shape. Three/four-model GET detail uses `answerMode:individual` and omits all per-run answer/evidence fields. The explicit summary endpoint uses that representation for any model count. Individual answer, citation-page and comparison reads are bounded to a complete 2MiB JSON envelope; excess returns 413 without truncation. Every individual answer read, for any model count, omits `run.result.citations` and adds `citations:{count,pageSize:20}`. A null count means the answer is unavailable or expired; zero means a retained answer genuinely has no citations. The cited-source endpoint returns `{role,runId,comparisonId,resultExpired,total,offset,nextOffset,items}` and requires exactly one offset from `0,20,40,60,80,100`; duplicates, extra fields and other values are refused. Source pages keep the original order and full canonical URLs. Offset100 is an allowed empty terminal page for the maximum100 citations. Expired/unavailable evidence returns no items, null total and null next offset, never a fabricated zero count.

All start, same-key replay, cancellation and reconciliation acknowledgments now use the bounded summary representation with `answerMode:individual`, for every1–4 model count. They contain no per-run answer, generation or detailed evidence fields; the client reads those through the separate current-authority individual endpoint. The complete acknowledgment, including any reconciliation outcome, stays below2MiB. This intentionally changes legacy1/2 mutation acknowledgment shapes, while preserving legacy GET detail. It must deploy with the corresponding new UI contract: all result cards load summary, text and source pages separately. The new UI is not implemented or accepted by this backend checkpoint.

All these reads require the same current project role as history and do not grant an API-key scope or export raw private receipt fields. Only the citation-page endpoint accepts its one offset; other execution routes still reject query parameters. All comparison read paths use one fresh materialized database clock after workspace/project lock waits, shared by copied-input and answer expiry. Each individual answer and citation page likewise applies its own fresh cutoff in SQL after current authority, so a later page cannot bypass expiry or membership revocation. SQL projects answer text without citation bodies, or selects only the requested20 source items using ordinality; it does not fetch the complete citation array into Node for slicing.

This split preserves admitted evidence:100 legal2048-character Unicode citation URLs can expand during URL canonicalization while the original provider response stays below2MiB. A complete normalized answer can therefore exceed the output bound. The legacy one/two-model aggregate may return413; the bounded summary, individual text and source pages remain separately readable. No parser limit, URL, answer, source or paid request is dropped/truncated, and the response ceiling is unchanged. These reads also correct legacy one/two-model reads that could expose evidence expiring during a lock wait; cleanup lag never authorizes expired payloads.

Only free endpoint metadata is concurrent: at most two 10-second, 2MiB reads run at once, with results retained in selection order. Every started read settles before a failed batch is returned. Catalog refresh and key checks retain their existing limits. Paid requests remain sequential. Suggestion and content-support entry points still supply exactly one model; this comparison increment does not broaden their selection.

## Money and dispatch

The reservation is the selected endpoint's full published prompt capacity multiplied by its input price, plus the chosen output allowance and optional request fee. Decimal and exponent prices use integer coefficients; all terms are summed before a single upward microUSD rounding step. Node 24 preserves the original numeric cost lexeme in response JSON. The ledger keeps the rounded charge and the original reported amount separately. Token counters never substitute for billing evidence.

This is a conservative ceiling under the verified provider contract, not an external invoice guarantee. It excludes credit-purchase fees, taxes and upstream provider-account BYOK invoices. Ordinary OpenRouter-funded API keys are supported without account changes; management keys and free-tier accounts are rejected. The caller explicitly confirms funded-credit use. OpenRouter does not expose a verified per-request BYOK-disable control in this adapter: an unexpected BYOK response records its credit charge, clearly separates the external invoice and keeps a diagnostic; nothing pauses (owner decision D3).

The public endpoint catalog may omit optional request fees and include numeric `discount: 0`. Omission becomes a zero fee, also sent as the request-price ceiling; nonzero discount metadata or unsupported billable dimensions fail readiness. Standard prompt/completion prices are required. Nonzero cache-write/search/reasoning prices are unsupported. Text-only requests contain no tools, search, media or cache-write controls. New quotes use the existing catalog text profile, verified text architecture/reasoning policy and a unique fixed endpoint leaf, with disabled context compression. Legacy quotes preserve their original base-OpenAI route and request bytes; they still reject additional `openai/*` variants.

Immediately before each paid call, the worker rechecks read-only endpoint metadata, then commits a fresh role, archive, key-revision, manual-pause and uncertain-charge check together with `dispatched`. All selected children are reserved in one transaction and run sequentially; failure to reserve the fourth rolls back the preceding three and the comparison. The queue has zero automatic retries. Duplicate workers cannot resend a dispatched child. Transport loss, missing/unknown finality or a crash after dispatch leaves a charge uncertain and cancels undispatched siblings. Manual cancellation never invents a refund.

Owner decision D3: Start authorizes every child. A quote still expires after five minutes, but only Start checks its age; a started child is never cancelled because its quote aged, whether at its dispatch gate, the recurring-grant check or the sweeper. Each child runs on its own: there is no earlier-sibling gate, a refusal before dispatch cancels only that child, and children may finish in any order; the comparison is complete when no child is queued or running. Start enqueues one `{executionId}` job per uncached child (zero retries, 180-second expiry) in the transaction that reserves it, and each child runs as its own job; for one release the worker still drains `{comparisonId}` jobs queued before this change by running their children in position order. The prompt queue polls every 0.5 seconds (the pg-boss floor), so one worker still starts up to four children per former 2-second comparison poll; children run one at a time per worker. The sweeper works per child: a child still running 90 seconds after dispatch becomes uncertain (the existing crash rule), and a queued child with no live job keyed by its own ID or its comparison's ID is cancelled alone. A child waiting behind slow siblings is covered by its own live job, so the sweeper does not cancel it. Future agent sub-tasks (P61, no code yet) follow the same rule: one zero-retry job per sub-task, reserved and enqueued at Start in one transaction, each with its own time limit and no quote clock after Start, and the parent derives completion from its children.

Prompt suggestions are single runs and still require their five-minute quote to remain valid at persisted dispatch authorization. An already-expired queued suggestion cancels its unused reservation before credential decryption or read-only endpoint requests. After endpoint, context and key checks, the final authorization update rechecks quote expiry against the database clock; failure rolls back dispatch and cancels the unused reservation. This authorizes a subsequent HTTP request, whose scheduling is not guaranteed by the quote clock. Expiry after dispatch leaves known-charge settlement, proposal validation, uncertain-charge recovery and idempotent replay intact. Quote validity is separate from the default 90-day raw-evidence retention period.

## Receipts and retention

The generation header is saved before bounded response parsing. Valid terminal charge evidence remains recorded when the answer is empty, malformed or unsafe for PostgreSQL. Missing terminal evidence retains the reported amount as unresolved evidence, rather than settling a provisional zero. An OpenRouter 402, or a 403 whose `limit_source` is a key, guardrail or workspace budget, with no generation header, `id`, `usage` or `choices` is a refusal before any work: the comparison child or suggestion fails with a settled US$0.000000 receipt and a fixed message, nothing becomes uncertain and comparison siblings still run ([refusal contract](foundation.md#account-api-key-and-provider-controls)). Answers are untrusted text; only actual provider citation annotations become safe HTTPS links. Links found merely inside answer prose are not citation evidence.

Reconciliation uses only the saved generation ID and original key identity, exact model/provider, dispatch time, session ID and stored actor pseudonym. Those fields are documented in generation metadata; missing, conflicting or pending values remain inconclusive. The actor is stored at quote time, and key identity is a domain-separated SHA-256 fingerprint kept only server-side, so login-secret rotation does not orphan receipts. A matched lookup can recover the credit charge without recovering the answer. No ID means no lookup, balance inference or automatic resend.

Generated answers/citations and copied execution input are **raw provider evidence**, using the workspace's default **90-day** period. Copied input expires only after all children leave queued/running and their completion times precede the cutoff. This includes old uncertain outcomes: their generation IDs, actor/key binding, route, exact charge evidence, ledger and idempotency receipts remain. Authored prompt-library versions remain. DTOs report `resultExpired` and `inputExpired`; purged payloads are null, never presented as a genuinely empty original. Google and keyword results continue using derived-history retention (365 days by default). Unused expired quotes are removed after 24 hours. Batches are bounded and share the existing workspace/project transaction with the other cleaners.

## Seven-day per-model reuse (source increment; validation pending)

`reuseCached` is optional. Omission preserves legacy paid quoting and request input shape; `true` permits eligible reuse, while `false` explicitly requests fresh paid answers. The current UI defaults to reuse when the server advertises it and offers “Request fresh answers”. A quote previews every hit/miss and reserves only new requests. A zero new-spending reservation is not a zero-cost provider ledger entry.

The server hashes project/workspace, connection revision/key fingerprint, observed model canonical slug/requested model, endpoint leaf/provider, request profile and fixed inference policy, exact system message, case-preserving whitespace-normalized user text and output allowance. Prompt/version IDs and selected-model ordering do not substitute for semantic identity. The actual authored input and paid request bytes remain unchanged. Catalog canonical identity is provider metadata, not an immutable-weight attestation; in-place model updates may not be detected. Answers can be up to seven days old. Legacy answers without the captured identity are not retroactively promoted into cache entries.
